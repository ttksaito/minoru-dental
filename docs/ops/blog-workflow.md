# ブログ投稿のフロー（2026-11-14 整理）

運営者（院長の次男）が院長の監修なしで書いて公開する前提のフロー。
Claude Code に手伝わせるときの貼り付け文も各段階に書いてある。

## 全体像

```
① ネタを決める（10分）
   └ ダッシュボードの検索キーワード／患者さんによく聞かれること／下書きストック
② 下書きを書く（60〜90分）
   └ CMS のエディタに直接 or Claude に骨子を出させて肉付け
③ セルフチェック（10分）
   └ 下のチェックリスト。Claude に読ませて指摘を受けるのも可
④ サムネイル（5分）
   └ 横長 1200×630 目安、WebP か JPG。CMS でアップロード
⑤ 公開（1分）
   └ CMS の「公開」ボタン → 自動ビルド → 数分で本番に反映
⑥ 公開後の確認（5分）
   └ 本番で表示・スマホ表示・OGP を確認
⑦ 2〜4週間後に数値を見る（5分）
   └ ダッシュボードの「検索から来られたページ」「よく見られたページ」
```

目標ペース: **週 1 本**。無理なら隔週。1 本の長さは見出し 3〜5 個、1,500〜2,500 字が目安。

## ① ネタを決める

優先順位の高い順:

1. **ダッシュボードの検索キーワードで、表示はあるのにクリックがないもの**。すでに Google が「このサイトはこの話題に関係ある」と判断しているので、記事を足すと順位が上がりやすい。例（11/14 時点）: 「東松山 歯医者 日曜日」「子供 歯磨き」「歯医者 質問」「定期検診 頻度」
2. **受付や診療で患者さんによく聞かれること**。院長やスタッフに「最近よく聞かれる質問は？」と聞くだけでよい
3. **下書きストック**（`content/drafts/`、下記）
4. 季節ネタ（新学期の歯科検診、年末年始の休診前の駆け込み、など）

地名を入れられるネタは入れる。「東松山市で子どもの歯医者を探すときに見るポイント」のように、地域の人が検索する形にすると、医院名以外の検索で見つかるようになる。

Claude への貼り付け例:
```
ブログのネタを 5 つ提案して。ダッシュボードの検索キーワードと既存記事（blog-posts.json）を踏まえて、まだ書いていない話題で。
```

## ② 下書きを書く

**書き手の立場**: 運営者（院長の息子）の視点で書く。「私は歯科医ではないので」「院長に聞いたところ」と立場を明示してよい。公開済みの『初めて（久しぶりに）歯医者に行く前に…』がこのトーンの見本。

**構成の型**:
- 冒頭 2〜3 行: 誰のどんな悩みに答える記事かを書く（ここが一覧ページの要約にもなる）
- 見出し（##）3〜5 個: 疑問 → 答え → 理由 → 具体的にどうするか
- 最後: 「気になる方は受診を」の一文と、当院への案内（電話・LINE・診療時間へのリンク）

**医療情報の書き方**（院長監修なしで公開するための線引き）:
- 一般に知られている予防・生活習慣の話は書いてよい（歯磨きの仕方、定期検診の間隔、食事と虫歯の関係など）
- 個別の診断・治療法の優劣・薬の話は書かない。「〜の可能性があります。歯科医院で診てもらってください」の形にする
- 断定を避ける。「必ず」「絶対」「治る」は使わない
- 出典が必要な数字（有病率など）は、厚労省・日本歯科医師会など公的な出典を 1 つ添える。出典が出せない数字は書かない
- 著者欄は「サイト運営」にする。「院長」は院長本人が読んで OK を出した記事だけ

**書く場所は 2 通り**:
- A. CMS（https://www.minoru-dental.jp/admin/）の「新規作成」で直接書く。保存すると「下書き」として残り、公開するまで本番には出ない。おすすめ
- B. Claude に骨子を出させてから CMS に貼る。貼り付け例:
```
「東松山市で子どもの歯医者を探すときに見るポイント」というタイトルでブログ記事の下書きを書いて。運営者（院長の息子）の視点、見出し 4 つ、2,000 字程度。医療的な断定はせず、最後に当院の案内を入れて。
```

## ③ セルフチェック（公開前に 1 回読む）

- [ ] 冒頭 2〜3 行だけ読んで、誰向けの何の記事か分かる
- [ ] 見出しだけ拾い読みして話の流れが分かる
- [ ] 「必ず」「絶対」「治る」「〜すべき」がない
- [ ] 治療法や薬の優劣を書いていない。症状の話は「受診を」で締めている
- [ ] 数字には出典がある（または数字を消した）
- [ ] 当院の情報（診療時間・電話・住所）がサイトの記載と一致している
- [ ] タイトルに検索されそうな言葉が入っている（「〜とは」「〜の方法」「東松山」など）
- [ ] スラッグ（URL）は英小文字とハイフンだけ。公開後は変えない
- [ ] 要約（summary）は 100〜150 字で、冒頭の繰り返しでなく記事の結論が分かる

Claude への貼り付け例:
```
content/blog/xxxx.md を docs/ops/blog-workflow.md のチェックリストで確認して、直すべき点だけ挙げて。
```

## ④ サムネイル

- 横長（1200×630 ピクセル目安）。スマホ一覧でも分かる大きめの要素 1 つ
- 形式は WebP か JPG。ファイル名は英数字（例: `child-dentist-guide.webp`）
- CMS の「サムネイル画像」欄にドラッグ＆ドロップすると `blog/uploads/` に入る
- 作り方の候補: Canva のテンプレート、生成 AI 画像、医院の写真。人物写真は本人の了承を取る
- 迷ったら、医院のイラスト素材（`image/` にあるもの）＋ タイトル文字で統一感を出す

## ⑤ 公開

1. CMS の記事画面で「公開」→「公開する」
2. 数分で GitHub Actions がビルドし、本番に反映される（`https://www.minoru-dental.jp/blog/スラッグ/`）
3. 公開日（date）は実際に公開する日にする。過去日にすると一覧で下に埋もれる

反映されないときは、GitHub の Actions タブで「ブログの自動ビルド」が失敗していないか見る。失敗ログを Claude に貼れば原因を調べられる。

## ⑥ 公開後の確認

- 記事 URL をスマホで開く。画像・見出し・リンクが崩れていない
- LINE やメッセージで URL を自分宛てに送り、サムネイルとタイトルが出る（OGP）
- 余裕があれば Google ビジネスプロフィールの「投稿」に記事リンクを載せる（地図経由の読者が増える）

## ⑦ 数値を見る（2〜4 週間後）

ダッシュボード（https://www.minoru-dental.jp/dashboard/）で:
- 「検索から来られたページ」に記事が出てきたか、どのキーワードで表示されているか
- 「よく見られたページ」で読まれているか
- 表示はあるのにクリックが少なければタイトルと要約を直す（`updated` を入れて再公開）

## 下書きストック（content/drafts/）の扱い

2026 年 8 月に Claude が書いた 9 本の下書きが `content/drafts/` にある。当時は院長監修前提の説明口調で書かれているので、**そのまま公開せず、運営者の視点に書き直してから**出す。

| ファイル | タイトル | 扱い |
|---|---|---|
| dry-mouth-cavities | 口が乾くとなぜ虫歯になりやすい？ | 公開候補 |
| floss-before-or-after | デンタルフロスは歯磨きの前？後？ | 公開候補 |
| sugar-amount-vs-frequency | 虫歯になりやすいのは甘いものの「量」より「回数」？ | 公開候補 |

| painless-periodontal-disease | 歯周病はなぜ痛くない？ | 公開候補（症状の話なので「受診を」を強めに） |
| teeth-vs-bones | 歯は骨と同じもの？ | 公開候補（豆知識枠） |

Claude への貼り付け例:
```
content/drafts/dry-mouth-cavities.md を運営者視点のトーンに書き直して、docs/ops/blog-workflow.md のチェックリストを満たす形で content/blog/ に移して。公開日は今日。サムネイルは後で CMS から差し替える前提で仮の画像を指定して。
```

## 仕組みのメモ（触らなくてよい部分）

- 記事の実体は `content/blog/スラッグ.md`。CMS もローカル編集も最終的にここに書く
- `content/blog/` が変わると GitHub Actions（`build-blog.yml`）が記事 HTML・一覧・sitemap を自動生成してコミットする。ローカルで `npm run build:blog` を打つ必要はない
- タグは空で保存しても本文から自動判定される（`admin/tag-keywords.json`）
- 記事ごとの閲覧数は GA4 → 人気記事ランキング（`popular-posts.json`、毎朝更新）と、ダッシュボードに出る
