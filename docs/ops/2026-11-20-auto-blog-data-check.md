# ブログ自動作成がダッシュボードの全データを使えたかの確認（2026-11-20）

## カレンダーのプロンプト

```
docs/ops/2026-11-20-auto-blog-data-check.md を読んで、今朝のブログ自動作成のログを確認して。
```

## 背景

- 11/17 の定期実行（routine `trig_01YAV7MzCNJ3kzaV7CBgbaAy`）では、パスワード（`DASHBOARD_PASSWORD`）は環境に設定済みで、復号も成功していた
- しかし復号スクリプトの要約の最後に出た「ビジネスプロフィール: 未取得（…429…）」を、エージェントが復号失敗と読み違え、`insights.json` だけで進めた
- 11/18 に対策（コミット b488064）: スクリプトの最後に「復号成功: …」を出す、`auto-blog.md` に成否の判断方法を追記
- 11/20 6:06 JST の実行で効いているかを確認する

## Claude がやること

1. `RemoteTrigger` の `list_runs`（trigger_id `trig_01YAV7MzCNJ3kzaV7CBgbaAy`）で 11/20 の実行を探し、`get_run_log` でログを読む
2. 次を確認する
   - `DP=set` などで環境変数があること
   - `node scripts/decrypt-dashboard-data.js` の出力に「復号成功」が出ていること
   - エージェントが `dashboard/data.json` を読んでネタを選んだこと（最終報告に「insights.json だけで進めた」と書いていないこと）
   - 下書き PR が 3 本以上で作成をスキップした回なら、復号まで進まない。その場合は次回（3 日後）の確認予定を作る
3. 結果を運営者に短く報告する
   - 使えていた → この手順書の先頭に「状態: 確認済み」と書いて終了
   - まだ読み違えている → ログの該当箇所を示し、routine のプロンプト（要点の「ダッシュボードの全データを復号して読む」）にも成否の判断方法を足す案を出す
4. ダッシュボード側のビジネスプロフィール取得が 429 のままかも、復号した data.json の `errors.gbp` で分かれば併せて伝える（直すかは運営者と相談）
